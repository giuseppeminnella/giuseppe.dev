C · slowing down, where the time goes, the pipeline

Slowing down does not mean typing slower. It means small steps, each followed by a correction.

The line never wanders far. You pay a little alignment, often, instead of a lot at the end.

Fast or slow, the arrival is the same. The slow one kept control all the way.

Why the same? Because writing code is 16% of a developer’s time.

Make coding 30% faster and the whole week ends about 5% sooner.

Even if code took no time at all, you would finish at most 16% sooner.

Look at the line as a pipeline. Every stage has a width, and the narrowest one sets the pace.

AI made code three times wider. Nothing else changed, so nothing ships faster.

Worse: spare firing power, no clear target. Code fires anyway, work nobody asked for jams review, and the real work ships slower.

It is a game of equilibrium: widen every stage together, starting from the narrowest.

IDC, How Do Software Developers Spend Their Time?, February 2025 (2024 data). The 5% and the 16% are arithmetic on IDC’s 16%.

Pipeline after Andrew Murphy, “If you thought the speed of writing code was your problem, you have bigger problems”.
